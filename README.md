# Генераторы Calltouch

Актуально на 11 августа 2026 года. Это статическое приложение на HTML, CSS и чистом JavaScript: сборщика, серверной части сайта и установки пакетов нет.

## Что находится в проекте

- **Баннеры** — шесть адаптивных рекламных форматов из одного набора данных.
- **Карточки кейсов** — слайды 1920×1080 с экспортом в двойном разрешении.
- **Рассылки** — отдельный редактор брендированных HTML-писем.

`index.html` пока объединяет баннеры и карточки кейсов. Рассылки вынесены в самостоятельную страницу `email.html` и отдельные модули в `email/`. Новые крупные генераторы также следует делать отдельными страницами, не связывая их состояние и экспорт с существующим старым экраном.

Опубликованная версия: `https://case-carder.vercel.app/`. Отдельная страница рассылок: `https://case-carder.vercel.app/email.html`.

## Локальный запуск

Для просмотра можно открыть HTML-файл напрямую. Для чтения DOCX, загрузки шрифтов и создания PNG надёжнее запускать проект через Live Server или другой локальный HTTP-сервер.

- `index.html` — баннеры и карточки кейсов;
- `email.html` — рассылки;
- `http://127.0.0.1:5501/email.html` — типичный адрес Live Server, но порт может отличаться.

Если создание фирменного PNG локально заканчивается ошибкой `Failed to fetch`, сначала проверить CORS функции. Актуальная версия `cloud/email-brand-assets/index.py` разрешает `localhost`, `127.0.0.1` и `::1` на любом порту. Старую опубликованную версию функции необходимо заменить архивом `cloud/email-brand-assets/email-brand-assets.zip`.

## Архитектура рассылок

Основные файлы:

- `email/email-model.js` — типы блоков, исходные значения, дизайн-токены и состояние письма;
- `email/email-parser.js` — чтение обычного текста, TXT и DOCX, сборка двух вариантов;
- `email/email-renderer.js` — предпросмотр и итоговый табличный HTML письма;
- `email/email-quality.js` — нормализация и проверка перед экспортом;
- `email/email-app.js` — интерфейс, редактирование, холст, сохранение, экспорт и публикация PNG;
- `email/email-brand-title.js` — простой заголовок Dela;
- `email/email-brand-scene.js` — сложная фирменная композиция;
- `email/email.css` — интерфейс редактора;
- `shared/assets.js` — локальные и публичные адреса ассетов;
- `shared/email-config.js` — публичный адрес функции загрузки, без секретных ключей;
- `cloud/email-brand-assets/` — исходник и готовый ZIP функции Yandex Cloud.

Состояние рассылки хранится в `localStorage` под ключом `calltouch-email-project-v1`. Баннеры и карточки используют своё отдельное состояние. Формат данных между генераторами не объединять без отдельного решения по миграции.

## Сценарии создания письма

### Автоматическая сборка

- вставка обычного текста;
- загрузка TXT;
- загрузка DOCX через локальную JSZip, без отправки документа на сервер;
- детерминированный разбор заголовков, абзацев, списков и HTTPS-ссылок без нейросети;
- два варианта: «Модульный» и «Последовательный»;
- переход в обычный редактор после выбора варианта.

Текущий разборщик намеренно простой. Первая подходящая строка становится заголовком. Пустые строки разделяют смысловые группы. Для автоматической раскладки используется максимум четыре раздела после заголовка (`slice(0, 4)` в `sectionBlocks`). Остальной текст сейчас не попадает в собранный макет. Это известное ограничение, а не ошибка чтения DOCX; при дальнейшем развитии разборщика нельзя молча отбрасывать оставшиеся разделы.

### Ручная сборка

Доступные блоки:

- обычный заголовок;
- текст;
- акция;
- картинка с текстом;
- картинка на всю ширину сетки со ссылкой на весь блок;
- картинка на всю ширину сетки;
- заголовок Dela;
- фирменная композиция;
- карточка;
- преимущества 2×2;
- финальный призыв;
- отдельная кнопка;
- разделитель.

Блоки можно добавлять, выбирать на холсте, редактировать прямо в письме, дублировать, удалять, временно скрывать и перемещать стрелками или перетаскиванием в боковой панели. Скрытый блок остаётся в структуре, но не показывается в предпросмотре и не попадает в итоговый HTML; иконка глаза возвращает его. Поля сохраняются без полной перерисовки на каждый введённый символ; предпросмотр обновляется после завершения изменения.

## Холст рассылки

- режимы «Компьютер» 660 px и «Телефон» 390 px;
- кнопки уменьшения и увеличения масштаба;
- «Вписать» показывает письмо целиком в доступной области;
- `Ctrl`/`Cmd` + колесо меняет масштаб;
- обычное колесо перемещает письмо вертикально внутри холста;
- зажатое колёсико или пробел + перетаскивание двигает холст;
- ссылки в предпросмотре не открываются, поэтому системная отписка не уводит из редактора;
- текущая позиция письма сохраняется при обновлении предпросмотра.

Мобильный предпросмотр использует отдельный viewport 390 px и те же адаптивные ограничения, что и итоговый HTML: фиксированные desktop-ширины таблиц, изображений и внутренних плашек не должны вылезать за контентную сетку. Социальные иконки сохраняют компактную таблицу, а не растягиваются на всю ширину. После переключения режима iframe перерисовывается с актуальным viewport.

## Структура итогового письма

Основная оболочка имеет ширину 660 px, внутренняя сетка контента — 604 px. Логотип, основной контент, сноски, социальный блок и дисклеймер выровнены по этой сетке. В письмо автоматически добавляются:

- тёмный логотип Calltouch;
- подпись «С уважением, Команда Calltouch»;
- редактируемые сноски;
- Telegram, MAX, VK и YouTube;
- ссылка на веб-версию;
- системная отписка.

В итоговом HTML используются переменные eNkod `{{link_view_in_browser}}` и `{{link_unsubscribe}}`. В предпросмотре клики перехватываются. Для отправки рекомендуемый путь — скопировать или скачать итоговый HTML и использовать HTML-редактор eNkod; повторная сборка через Stripo может изменить таблицы, стили и системные переменные.

## Брендовая типографика и сложный дизайн

Почтовые клиенты нестабильно поддерживают подключаемые шрифты, градиенты, сложные рамки, наложения и абсолютное позиционирование. Поэтому обычные HTML-блоки используют безопасные запасные шрифты:

- вместо Dela Gothic One — `Arial, Helvetica, sans-serif` с жирным начертанием;
- вместо Museo Sans — `Arial, Helvetica, sans-serif`.

Два специальных блока сохраняют брендовый вид через PNG:

### Заголовок Dela

- только заголовок и фон, без дополнительной иллюстрации;
- пять брендовых цветовых схем и свой цвет;
- автоматический выбор белого или тёмно-синего текста по максимальному контрасту;
- ручной выбор цвета текста при необходимости;
- размер шрифта зависит от длины текста;
- минимальная высота 104 px, далее блок растёт по фактическому количеству строк.

### Фирменная композиция

- заголовок Dela;
- список тезисов;
- одна из трёх градиентных схем;
- необязательный фоновый ассет;
- необязательная иллюстрация, выходящая за внутреннюю плашку;
- минимальная высота 270 px, далее блок растёт вместе с заголовком и тезисами;
- необязательная ссылка со всего изображения.

В редакторе оба блока остаются живой HTML-композицией. Кнопка «Создать изображение» измеряет фактическую высоту, создаёт PNG через `vendor/dom-export.js`, загружает его в Object Storage и записывает URL в состояние блока. Если после публикации изменены текст, схема или ассет, подпись содержимого перестаёт совпадать и экспорт блокируется до повторного создания PNG.

### Dela внутри текстовых полей

Фрагменты в маркерах `%%текст%%` поддерживают inline-редактирование. До публикации в предпросмотре используется адаптивный fallback с переносом внутри доступной ширины; в мобильном режиме его размер — 14 px, чтобы приблизить поведение будущего PNG. После проверки и загрузки Dela-фрагментов в облако предпросмотр автоматически переключается на те же PNG, которые попадут в экспорт. PNG генерируется с шириной фактического desktop-текстового блока, поэтому переносы не меняются из-за того, что экспорт запущен из режима телефона.

Для обычных абзацев и списков Dela не заменяет живой критичный текст в экспортируемом письме: это только брендовый визуальный фрагмент. При изменении содержимого требуется повторная публикация PNG.

Изображение гарантирует фирменный шрифт и сложный дизайн, но текст внутри него нельзя выделить, а при отключённых картинках виден только `alt`. Важный юридический текст и критичные действия не следует превращать в картинку.

## Ассеты и Yandex Object Storage

Итоговые ссылки строятся от `https://calltouch-public.website.yandexcloud.net/`. Это публичный адрес Object Storage. Созданный ресурс Cloud CDN и домен `cdn.calltouch.ru` код сейчас не использует: для перехода на него потребуется рабочая DNS-запись и замена `PUBLIC_BASE_URL` в `shared/assets.js`.

Постоянные файлы не загружаются в облако автоматически. В бакете `calltouch-public` должны существовать те же пути, что указаны в проекте:

- `visuals/...`;
- `logos/...`;
- `icons/...`;
- `icons/essentials/...`;
- `backgrounds-light/...`.

Локальные `previewSource` используются только в редакторе. В итоговое письмо попадает `exportUrl`. Если объект по этому адресу не загружен, предпросмотр в генераторе может выглядеть нормально, а в отправленном письме картинка будет сломана. Для своего изображения требуется абсолютный публичный HTTPS-адрес; `blob:`, `file:`, `data:` и обычный HTTP валидатор считает ошибкой.

## Функция публикации PNG

Функция находится в `cloud/email-brand-assets/index.py`, готовый архив — `cloud/email-brand-assets/email-brand-assets.zip`, точка входа — `index.handler`, среда — Python 3.12.

Запрос: `POST` с JSON-полями `imageBase64` и `blockId`. Два режима:

- брендовый PNG (по умолчанию) — только PNG до 2 МБ, шириной 600–1600 px и высотой 180–1200 px, объект сохраняется по пути `email-assets/production/YYYY/MM/<block>-<hash>.png`;
- произвольная картинка блока (поле `kind: "asset"`) — PNG, JPEG, WebP или GIF до 2 МБ без ограничений по размерам, путь `email-assets/uploads/YYYY/MM/custom-<hash>.<ext>`. Этим режимом пользуется кнопка «Использовать» в модалке своего изображения: выбранный локальный файл автоматически улетает в облако и получает публичный URL, ручная ссылка больше не обязательна.

В обоих режимах объект кешируется на год и возвращается как публичный URL.

Переменные окружения функции:

- `S3_BUCKET=calltouch-public`;
- `S3_ENDPOINT=https://storage.yandexcloud.net`;
- `S3_ACCESS_KEY_ID`;
- `S3_SECRET_ACCESS_KEY`;
- `PUBLIC_ASSET_BASE_URL=https://calltouch-public.website.yandexcloud.net`;
- `ALLOWED_ORIGINS=https://case-carder.vercel.app`;
- необязательный `UPLOAD_TOKEN`.

Функция должна оставаться публично вызываемой, иначе браузер не сможет отправить PNG. Сервисный аккаунт `email-brand-uploader` должен иметь только роль `storage.uploader` на бакет. Ключи хранятся исключительно в переменных функции. Не копировать их в `shared/email-config.js`, README, исходники, коммиты или диагностические сообщения. `references/generator-function.py` исключён через `.gitignore`, потому что содержит старые секреты; любые активные ключи из него нужно отозвать.

Текущая защита по Origin и необязательному токену не является полноценной авторизацией. Для закрытого внутреннего использования в будущем нужен API Gateway или авторизация портала.

## Проверка и экспорт рассылки

Перед экспортом редактор сначала автоматически догружает в облако всё неопубликованное: PNG фирменных блоков с устаревшей подписью и свои картинки, выбранные файлом без публичной ссылки (результат показывается в отчёте проверки). Затем валидатор проверяет пустые заголовки (блок «Заголовок» без текста просто не занимает места и ошибкой не считается), слишком длинные тексты, ссылки, количество конкурирующих кнопок, публичность изображений и актуальность PNG фирменных блоков. При ошибках копирование и скачивание HTML блокируются. После успешной проверки доступны:

- просмотр итогового кода;
- копирование HTML;
- скачивание `calltouch-email.html`.

Даже успешно проверенное письмо нужно отправить на тестовые адреса через eNkod и посмотреть минимум в Gmail, Apple Mail и Outlook. Табличная вёрстка и встроенные стили уменьшают различия, но не устраняют ограничения почтовых клиентов.

Валидатор принимает абсолютные HTTPS-ссылки (`https://...`) и штатные eNkod-переменные (`{{link_view_in_browser}}`, `{{link_unsubscribe}}`). Предупреждение появляется только для небезопасного протокола или некорректного адреса; обычная рабочая HTTPS-ссылка не должна считаться placeholder.

Кнопки форматирования в панели и на canvas работают только при наличии выделения. Без выделенного текста они ничего не вставляют и не создают служебные заглушки вроде `**жирный текст**`, `текст Dela` или `текст ссылки`. Доступны жирность, Dela, ссылка, список, ручной перенос и типографика. Иконки форматирования используют единый тяжёлый стиль; Dela обозначается буквой `D`, остальные — узнаваемыми системными геометриями.

## Публикация

Фронтенд публикуется из ветки `main` репозитория GitHub через Vercel. После отправки коммита проверить `https://case-carder.vercel.app/email.html`.

Функция Yandex Cloud не обновляется вместе с Vercel. После изменения `cloud/email-brand-assets/index.py` необходимо пересобрать или использовать лежащий рядом ZIP, открыть функцию `email-brand-assets`, загрузить архив как новую версию и сохранить прежние переменные окружения и сервисный аккаунт.

На момент обновления README создание PNG на опубликованном Vercel работает. Локальный Live Server получал CORS-ошибку от старой версии функции. Исправление для локальных адресов и динамической высоты PNG уже находится в исходнике и ZIP функции, но начнёт работать в облаке только после ручной публикации новой версии Yandex Cloud Function.

## Генератор баннеров

Поддерживаемые размеры:

- квадрат — 1080×1080;
- история — 1080×1920;
- портрет — 1080×1350;
- широкий — 1920×1080;
- реклама — 1200×628;
- реклама без текста — 1200×628, только фон и центральное изображение.

Все шесть размеров одновременно видны в рабочей области, обновляются синхронно, но используют самостоятельную композицию и отдельное положение основного изображения. Нажатие на нужный размер выбирает его для точной настройки и одиночного экспорта.

В панели доступны:

- заголовок с акцентной разметкой `[важный текст]`;
- циановый или цианово-пурпурный градиент для акцента заголовка и основной кнопки;
- два стиля заголовка;
- подзаголовок;
- две настраиваемые плашки с графитовой, белой или полупрозрачной серо-голубой палитрой;
- кнопка с заливкой, контуром или без рамки;
- светлая и тёмная тема с отдельными фонами и цветом текста;
- автоматический, светлый, тёмный или цветной логотип;
- шесть фонов для каждой темы;
- коррекция фона на 0%, 15% или 30%;
- автоматический или ручной выбор основного изображения;
- загрузка своего фона и основного изображения;
- перетаскивание изображения прямо на холсте;
- отдельная настройка положения изображения для каждого размера;
- классическая и альтернативная композиция;
- выравнивание, размер и ширина текста, поля и интервалы;
- режим ограничения текста до 20% площади баннера: показывает оценку доли текста, уменьшает заголовок и подзаголовок при необходимости и не даёт экспортировать формат, который всё равно превышает лимит;
- редактирование текстов прямо на баннере;
- масштабирование выбранного предпросмотра колесом над ним;
- автоматическое сохранение настроек в браузере между запусками;
- сброс к исходным данным.

После блока «Компоновка» находится сворачиваемая секция «Анимация». В ней доступны:

- таймлайн с воспроизведением, паузой, перезапуском и ручной прокруткой;
- длительность ролика от 1 до 6 секунд;
- направление появления текста: снизу, справа, сверху или слева;
- минимальное и максимальное смещение точки старта;
- задержка между появлением логотипа, плашек, заголовка, подзаголовка и кнопки;
- скорость и амплитуда покачивания основного изображения;
- отдельные диапазоны смещения, поворота и масштаба;
- зацикленный предпросмотр;
- экспорт текущего формата в MP4 и всех шести MP4 в ZIP.

Траектория изображения замыкается в конце ролика, поэтому MP4 можно ставить на бесшовный повтор.

Текст автоматически уменьшается до безопасного минимального размера. Если даже после подгонки он не помещается, приложение показывает предупреждение и не экспортирует сломанный макет.

## Экспорт баннеров

Для статичных баннеров доступны два режима:

- текущий формат в JPG 2x;
- все шесть форматов в одном ZIP-архиве.

Итоговые размеры файлов:

- `calltouch-creative-square.jpg` — 2160×2160;
- `calltouch-creative-story.jpg` — 2160×3840;
- `calltouch-creative-portrait.jpg` — 2160×2700;
- `calltouch-creative-landscape.jpg` — 3840×2160;
- `calltouch-creative-ad.jpg` — 2400×1256;
- `calltouch-creative-adVisual.jpg` — 2400×1256.

Архив сохраняется как `calltouch-creatives-2x.zip`.

Для анимированных баннеров доступны:

- текущий формат в `calltouch-creative-{format}.mp4`;
- все шесть форматов в архиве `calltouch-animations.zip`.

Видео записывается локально в MP4/H.264 с частотой 30 кадров/с и без звука. Генератор проверяет поддержку MP4 через браузерный `MediaRecorder`; если кодек недоступен, кнопки видеоэкспорта блокируются и показывается подсказка использовать актуальный Chrome, Edge или Safari.

## Ассеты

Используются локальные папки:

- `backgrounds/` — тёмные фоны WebP;
- `backgrounds-light/` — светлые фоны PNG;
- `visuals/` — основные изображения SVG, PNG или WebP;
- `logos/` — варианты логотипа;
- `fonts/` — локальные шрифты;
- `icons/` — социальные и служебные иконки;
- `vendor/` — DOM-экспорт, Lucide и JSZip;
- `shared/assets.js` — общая конфигурация изображений, логотипов и социальных ссылок;
- `email/` — модель, разбор текста, проверка, отрисовка, редактор и стили рассылок.

Библиотека изображений единая для баннеров и рассылок и описана в `shared/assets.js`. Если пользовательский файл не загрузился, на баннере остаётся встроенная геометрическая версия, поэтому макет не становится пустым.

Автоматический выбор изображения работает по ключевым словам из заголовка, подзаголовка и плашек. Список файлов и ключевых слов находится в `BANNER_VISUALS` внутри `script.js`.

## Карточки кейсов

Исходный генератор сохранён отдельной вкладкой. В нём доступны:

- тёмная и светлая тема;
- шесть тёмных и шесть светлых фонов;
- коррекция фона на 30%;
- один, два или три показателя;
- ручные переносы строк;
- редактирование текста прямо на слайде;
- экспорт JPG 3840×2160.

## Технические детали

- состояние старого экрана хранит активную вкладку, данные карточки и данные баннеров;
- email-состояние изолировано и сохраняется под отдельным ключом localStorage;
- каждый формат баннера имеет собственный холст и собственные координаты изображения;
- изображения и шрифты дожидаются загрузки перед экспортом;
- JPG создаются последовательно, чтобы не занимать лишнюю память;
- ZIP собирается локальной библиотекой JSZip;
- MP4 собирается из растровой основы, отдельных слоёв видимых текстовых элементов и слоя кей-вижуала через Canvas, поэтому DOM не перерисовывается на каждом кадре;
- панель управления не попадает в экспорт.

## Правила для дальнейших изменений

- Не переносить рассылки обратно в старый монолит `script.js`.
- Не менять формат `localStorage` без миграции старого сохранённого письма.
- При добавлении типа блока обновлять модель, редактор, отрисовку, нормализацию и проверку экспорта.
- При добавлении поля в фирменный PNG-блок включать его в функцию подписи, иначе изменение не потребует повторной публикации картинки.
- Не путать `previewSource` и `exportUrl`: первый может быть локальным, второй обязан быть публичным HTTPS-адресом.
- Не использовать Dela как живой критичный текст в итоговом письме без запасного варианта; для точного брендинга применять PNG-блок.
- Не обещать поддержку CSS по поведению браузера: итог проверяется в реальных почтовых клиентах.
- Не добавлять пакеты и сборщик без отдельной необходимости — сейчас проект открывается как обычная статика.
- Не использовать `references/` как рабочий исходный код. Там лежат ТЗ, макеты и локальные примеры, в том числе потенциально чувствительные.
- Не помещать ключи Yandex Cloud, SMTP, API или другие секреты в репозиторий. GitHub уже блокировал такой коммит защитой секретов.

Автоматических браузерных тестов и постоянного набора модульных тестов сейчас нет. После изменений минимум выполнить синтаксическую проверку затронутых JS/Python-файлов, `git diff --check`, ручной просмотр компьютера и телефона, создание тестового фирменного PNG, проверку экспортного HTML и тестовую отправку через eNkod.
